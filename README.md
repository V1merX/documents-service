# documents-service

Кеширующий веб-сервер для хранения и раздачи электронных документов.
Go, PostgreSQL, Redis.

## Запуск

Скопировать .example.env в .env и подставить свои значения:

    cp .example.env .env

Поднять всё одной командой:

    docker compose up --build

Поднимутся postgres, redis, применятся миграции, стартует приложение на порту 8080.

Локально без докера:

    go run cmd/api/main.go

В этом случае postgres и redis должны быть доступны по адресам из .env,
а миграции надо применить самому:

    goose -dir migrations postgres "$DATABASE_URL" up

## Переменные окружения

ADMIN_TOKEN токен администратора, без него нельзя зарегистрировать пользователя
HTTP_SERVER_ADDR адрес и порт http сервера
HTTP_SERVER_READ_TIMEOUT таймаут чтения запроса
HTTP_SERVER_READ_HEADER_TIMEOUT таймаут чтения заголовков
HTTP_SERVER_WRITE_TIMEOUT таймаут записи ответа
HTTP_SERVER_IDLE_TIMEOUT таймаут простоя соединения
HTTP_SERVER_MAX_HEADERS_BYTES максимальный размер заголовков
DATABASE_URL строка подключения к postgres
STORAGE_PATH каталог, где лежат тела загруженных файлов
REDIS_ADDR адрес redis
REDIS_PASSWORD пароль redis, можно пустой
REDIS_DB номер базы redis
REDIS_TTL время жизни записей в кеше
PG_USER, PG_PASSWORD, PG_DBNAME, PG_PORT нужны только docker compose

## API

Все ответы приходят в общем конверте:

    {
      "error": {"code": 123, "text": "so sad"},
      "response": {},
      "data": {}
    }

Поля присутствуют только если заполнены.

Регистрация

    POST /api/register
    тело json: {"token": "админский токен", "login": "...", "pswd": "..."}
    ответ: {"response": {"login": "test"}}

Логин минимум 8 символов, только латиница и цифры.
Пароль минимум 8 символов, минимум 2 буквы в разных регистрах,
минимум 1 цифра, минимум 1 символ не буква и не цифра.

Аутентификация

    POST /api/auth
    тело форма: login, pswd
    ответ: {"response": {"token": "..."}}

Загрузка документа

    POST /api/docs
    multipart форма:
      meta json вида {"name":"photo.jpg","file":true,"public":false,"token":"...","mime":"image/jpg","grant":["login1"]}
      json данные документа, может отсутствовать
      file сам файл
    ответ: {"data": {"json": {}, "file": "photo.jpg"}}

Список документов

    GET /api/docs?token=...&login=...&key=...&value=...&limit=20
    HEAD /api/docs?token=...
    ответ: {"data": {"docs": [...]}}

login опционален, без него вернётся список своих документов.
key и value задаются вместе, key берётся из списка: id, name, mime, file, public, created.
limit по умолчанию 20, максимум 100.
Список отсортирован по имени и дате создания.

Получение документа

    GET /api/docs/{id}?token=...
    HEAD /api/docs/{id}?token=...

Если документ файл, вернётся сам файл с нужным mime.
Если нет, вернётся {"data": {...}} с данными документа.

Удаление документа

    DELETE /api/docs/{id}?token=...
    ответ: {"response": {"{id}": true}}

Завершение сессии

    DELETE /api/auth/{token}
    ответ: {"response": {"{token}": true}}

## Коды ошибок

http статусы: 200 ок, 400 некорректные параметры, 401 не авторизован,
403 нет прав доступа, 404 не найдено, 405 неверный метод, 500 внутренняя ошибка.

Коды в поле error.code:
100 некорректный запрос
101 не прошло валидацию
200 нет токена или токен невалиден
201 неверный логин или пароль
300 нет прав на документ
400 документ не найден
500 внутренняя ошибка

## Как устроено

cmd/api точка входа
internal/domain модели и правила, без зависимостей от инфраструктуры
internal/service бизнес логика, работает с интерфейсами хранилищ
internal/transport/http хендлеры, роутер, конверт ответа
internal/infrastructure/postgres репозитории
internal/infrastructure/redis кеш
internal/infrastructure/storage файлы на диске
internal/di сборка зависимостей
migrations миграции goose

## Кеш

GET и HEAD отдаются из redis. Кешируются отдельно документы по id
и списки по составному ключу из запрашивающего, владельца, фильтра и лимита.

Инвалидация выборочная. При загрузке и удалении документа сбрасываются
только списки тех пользователей, кто этот документ видит, то есть владельца
и всех из grant. Для этого ключи списков складываются в множества
lists:index:логин, при инвалидации берётся их объединение.
Списки остальных пользователей остаются в кеше.

Тела файлов больше 1 мегабайта в кеш не кладутся, они читаются с диска.

Если redis недоступен, запрос не падает, а идёт в базу.

## Хранение файлов

Файлы лежат на диске, в базе хранится только относительный путь.
Так строка в таблице остаётся лёгкой и выдача списка не тянет из базы
содержимое всех документов.

Каталог задаётся через STORAGE_PATH, в docker compose примонтирован том doc_files.
Файлы раскладываются по подкаталогам из первых двух символов id,
чтобы в одной папке не копились сотни тысяч файлов.
Запись идёт во временный файл с последующим переименованием,
поэтому читатель никогда не увидит недописанный файл.

## Безопасность

Пароли хранятся как argon2id хеш, не в открытом виде.
Админский токен сверяется за постоянное время.
Имя колонки для фильтра key берётся из белого списка,
поэтому подставить туда sql нельзя.
Размер загружаемого файла ограничен.

## Что не сделано

405 и 404 отдаются роутером не в общем конверте, а пустым телом.
501 не реализован.
Нет singleflight, при промахе кеша под нагрузкой в базу уйдёт
несколько одинаковых запросов вместо одного.
Тестами покрыт только домен.
